# 0.2.0 — 2026-08-06

## Added

- **`reliefweb_get_job`** and **`reliefweb_get_training`** fetch a job posting or training listing by numeric ID with the full description, application/registration instructions, and metadata that `reliefweb_search_jobs`/`reliefweb_search_training` omit — completing the search → get pattern reports and disasters already had. Both resolve through `POST /v2/{jobs|training}` with an `id` filter under `preset: analysis` rather than the item endpoint, since `GET /v2/{jobs|training}/{id}` 404s on an expired posting or a concluded training. ([#14](https://github.com/cyanheads/reliefweb-mcp-server/issues/14))
- **`archive`** selector on `reliefweb_get_country` and `reliefweb_get_disaster` pages a curated profile list's archived entries — `keyContent`, `appealsResponsePlans`, `usefulLinks` — that the record's default response drops (2,328 archived `keyContent` links alone on SYR). Mutually exclusive with `sections`; supplying both throws `selector_conflict`. New `src/mcp-server/tools/profile-archive.ts`. ([#15](https://github.com/cyanheads/reliefweb-mcp-server/issues/15))

## Changed

- **`reliefweb_get_report`**, **`reliefweb_get_disaster`**, and **`reliefweb_get_country`** return a section outline — every section name and its real serialized size — instead of the whole record once it exceeds the response budget; a `sections` re-call resolves named sections plus identity metadata. Built on the framework's `outlineOnOverflow` / `selectSections` / `formatOutline` primitives (`@cyanheads/mcp-ts-core/utils`), wired once in new `src/mcp-server/tools/document-sections.ts` so all five by-ID detail tools — including the two new ones — behave identically. Nothing is truncated on any path. ([#16](https://github.com/cyanheads/reliefweb-mcp-server/issues/16))
- **`reliefweb://reports/{id}`** and **`reliefweb://disasters/{id}`** resource descriptions now say the resource always returns the whole record and point at the matching tool for an oversized one — resources have no way to carry a `sections` selector.
