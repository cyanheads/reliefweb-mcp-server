# 0.2.2 — 2026-09-20

## Added

- **README documents a Docker install path** — a `mcpServers` config block running `ghcr.io/cyanheads/reliefweb-mcp-server:latest`, alongside a `docker build`/`docker run` snippet under Local development.

## Changed

- **Argument rejection classifies as `InvalidParams`** (`-32602`) instead of `ValidationError`, carries `data.reason: "invalid_arguments"`, and appends a `Recovery: <hint>` line to the error text.
- **Tool errors carrying `data.reason` or a boolean `data.retryable` close `content[0].text` with `(reason <reason> · not retryable)`.**
- **A caller disconnecting mid-call classifies as `RequestCancelled`** (`-32011`) instead of an internal error.
- **`src/index.ts` declares `sessionMode: 'stateless'` explicitly** — a from-source HTTP deployment that never set `MCP_SESSION_MODE` previously resolved `auto` → `stateful` and now resolves `stateless`. The published container already ran stateless.

## Security

- **The ReliefWeb request URL no longer reaches client-facing error data.** Every ReliefWeb request carries the operator's registered `appname` in its query string, and `error.data` is forwarded to the client as `structuredContent.error.data` on a non-2xx response — so the appname reached any caller who triggered one. If you consider your `appname` exposed, rotate it.
