# 0.2.3 — 2026-10-09

## Changed

- **`sections` on the five `reliefweb_get_*` tools** rejects a name the fetched record does not carry (`-32602`, message `Unknown section: <name>. Available sections: …`, `data.unmatched` / `data.available`); before, it silently returned the identity fields alone. The framework's `selectSections` made this change (0.13.8, cyanheads/mcp-ts-core#477); the `sections` field description now says so.
- **`server.json`** — the npm entries launch with `runtimeHint: "npx"` and no arguments (before: `runtimeHint: "bun"` with `run start:stdio` / `run start:http`), and the `streamable-http` entry sets `MCP_TRANSPORT_TYPE` to `http` (template shape from 0.13.11).
- **Dockerfile** — dependencies install in a new `deps` stage on the build platform, cross-installed for the target with `--os`/`--cpu`; the OTel peers install through `scripts/install-otel.ts` from the framework's `peerDependencies`; `scripts/prune-musl-packages.ts` deletes musl-only bindings; the production stage copies `node_modules` from `deps`; `MCP_FORCE_CONSOLE_LOGGING` is no longer set; the base images move to `oven/bun:1.4.2`; the OCI description names country profiles.
- **`.env.example`** — adds the framework's current variables (`MCP_REQUEST_STATE_KEY`, `MCP_HTTP_RESUMABILITY*`, `MCP_LOG_RATE_LIMIT_*`, `LOG_TOOL_FAILURE_PAYLOADS*`, `LOG_LLM_INTERACTIONS`, `OTEL_EXPORTER_OTLP_{TRACES,METRICS,LOGS}_ENDPOINT`), moves `MCP_HTTP_MAX_BODY_BYTES` under Transport, and shows `MCP_HTTP_HOST` as `127.0.0.1`.
- **Ignore files** — `.gitignore` and `.dockerignore` cover every `.env*` (`.gitignore` keeps `.env.example`, `.env.template`, `.env.sample`), and `.dockerignore` adds the MCP registry token files; `.mcpbignore` excludes `docs/idea.md`, `logs/`, `.cache/`, `coverage/`, and `tests/` from the bundle; `package.json` `files` excludes `dist/*.mcpb`.
- **CodeQL workflow** — runs `actions` and `javascript-typescript` as a matrix, each uploading under `/language:<language>`.
- **Framework skills and scripts** — `framework-skills/`, the devcheck, lint-mcp, lint-packaging, skill-version, antipattern, and release-github scripts, and `CLAUDE.md` / `AGENTS.md` synced to mcp-ts-core 0.13.14.
- **`docs/design.md`** — decision 12 records that an unknown `sections` name is rejected, superseding the silent projection.

## Fixed

- **Changelog entries 0.1.5 and 0.1.6** no longer end in stray closing tool-markup tags.

## Security

- **#24 — the upstream error response no longer reaches client error data.** Before, `reliefweb_search_reports`, `reliefweb_search_disasters`, `reliefweb_search_jobs`, `reliefweb_search_training`, `reliefweb_list_countries`, and `reliefweb_list_sources` put the upstream `McpError` (ReliefWeb's response `body`, `status`, `statusText`) into `structuredContent.error.data.cause` on a rejected query or upstream failure. Now `data` carries only `reason`, `recovery`, and `requestId`, and the upstream error stays on the logged cause.

## Dependencies

- **`@cyanheads/mcp-ts-core` ^0.13.6 → ^0.13.14** — tool error results carry `data.requestId` and end with `request <id>` (0.13.10); arguments sent as a numeric string, an integer for a string, or `null` for an optional field are repaired before validation (0.13.9, 0.13.14); `ctx.log` notifications to the client honor `MCP_LOG_LEVEL` and mask sensitive fields (0.13.11); the Docker image installs dependencies in a build-platform `deps` stage and drops musl bindings (0.13.10, 0.13.11).
- **Dependencies** — `pino-pretty` ^13.1.3 → ^13.2.0; dev: `@biomejs/biome` ^2.5.14 → ^2.5.15, `@socketsecurity/bun-security-scanner` ^1.1.2 → ^1.1.3, `@types/node` ^26.6.1 → ^26.6.4, `ignore` ^7.0.9 → ^7.0.12, `tsc-alias` ^1.9.5 → ^1.9.7, `vitest` ^5.0.1 → ^5.0.3; Bun 1.4.0 → 1.4.2.
