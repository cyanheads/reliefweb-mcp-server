# 0.3.0 — 2026-10-26

## Added

- Added the reliefweb-guide skill resource for humanitarian research and opportunity workflows.
- **`reliefweb_search_training`** accepts `cost` and `training_language` filters and returns cost and delivery-language metadata separately from listing language. ([#34](https://github.com/cyanheads/reliefweb-mcp-server/issues/34))

## Changed

- **Page limits** above 1,000 for searches/lists or 100 for profile archives clamp with a requested/applied notice; `RELIEFWEB_CLAMP_LIMITS=false` restores strict schema maxima. ([#35](https://github.com/cyanheads/reliefweb-mcp-server/issues/35))
- **Plugin and bundle packaging** adds Agent Plugins manifests, ships the guide across installation surfaces, and preserves SDK skill runtime modules while pruning development files. ([mcp-ts-core#794](https://github.com/cyanheads/mcp-ts-core/issues/794))
- **Development tooling** adopts current framework skills, packaging validation, and audit classification.

## Fixed

- **`reliefweb_get_disaster` and disaster resources** retrieve archived alerts and their curated-link archives. ([#28](https://github.com/cyanheads/reliefweb-mcp-server/issues/28))
- **Date bounds** reject impossible calendar/time values locally with `invalid_date` and the affected field; valid end-of-day `24:00` retains next-day normalization. ([#30](https://github.com/cyanheads/reliefweb-mcp-server/issues/30))
- **`reliefweb_search_reports`** preserves supplied zero/negative disaster IDs and ignores empty raw filters with a notice instead of echoing them as applied. ([#29](https://github.com/cyanheads/reliefweb-mcp-server/issues/29))
- **`reliefweb_crisis_briefing`** resolves country names to ISO3 before filtered calls and keeps disaster-name/GLIDE lookup separate. ([#32](https://github.com/cyanheads/reliefweb-mcp-server/issues/32))
- **Query guidance** gives text-syntax recovery for rejected searches and corrects career-category examples. ([#25](https://github.com/cyanheads/reliefweb-mcp-server/issues/25), [#31](https://github.com/cyanheads/reliefweb-mcp-server/issues/31))
- **Response rendering** preserves literal metadata and URL destinations through CommonMark while retaining upstream narrative Markdown; body-field descriptions identify Markdown correctly.
