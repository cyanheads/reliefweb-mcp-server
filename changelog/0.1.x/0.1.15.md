# 0.1.15 — 2026-08-06

## Added

- **`upstream-errors.ts`** — classifies a ReliefWeb HTTP failure as a rejected query (`InvalidParams` / `InvalidRequest` / `ValidationError`) or a service failure, and folds ReliefWeb's own JSON error text into the thrown message so it reaches `content[]`, not only `structuredContent`. ([#20](https://github.com/cyanheads/reliefweb-mcp-server/issues/20))
- **`date-utils.ts`** — `resolveDateBound` normalizes a bare calendar date or any-offset ISO 8601 datetime to the single `YYYY-MM-DDTHH:MM:SS+00:00` shape ReliefWeb's range filters accept; a bare date resolves to start-of-day on a lower bound and end-of-day on an upper bound. ([#21](https://github.com/cyanheads/reliefweb-mcp-server/issues/21))
- **`pagination.ts`** — `lastPageOffset` and `pagedPastEndNotice` compute a page-aligned last-page offset and build the "offset past the end" notice shared by every paging tool. ([#22](https://github.com/cyanheads/reliefweb-mcp-server/issues/22))

## Changed

- **`reliefweb_search_reports` / `reliefweb_search_disasters` / `reliefweb_search_training`** `date_from`/`date_to`/`date_start_from`/`date_start_to` now accept a bare calendar date (e.g. `2024-01-15`) alongside a full ISO 8601 datetime; both resolve to the exact shape ReliefWeb requires. ([#21](https://github.com/cyanheads/reliefweb-mcp-server/issues/21))
- **`reliefweb_search_training`** defaults to a lower bound of the current timestamp when neither `date_start_from` nor `date_start_to` is supplied, so an unbounded search opens on upcoming courses instead of the oldest listing in the corpus; supplying either bound leaves the range exactly as given. ([#17](https://github.com/cyanheads/reliefweb-mcp-server/issues/17))
- **Error contract** on all six tools (`search_reports`, `search_disasters`, `search_jobs`, `search_training`, `list_countries`, `list_sources`) — a rejected query now throws `invalid_query` (`InvalidParams`) instead of the generic `upstream_error`; both reasons quote ReliefWeb's explanation when one was sent. ([#20](https://github.com/cyanheads/reliefweb-mcp-server/issues/20))

## Fixed

- **Paging past the end of a result set** on all six tools reported "no matches" and suggested loosening filters, even when the query matched thousands of records. The empty-page notice now distinguishes a genuine zero-match query from an offset run past the end, naming `totalCount` and the last reachable offset in the latter case. ([#22](https://github.com/cyanheads/reliefweb-mcp-server/issues/22))
