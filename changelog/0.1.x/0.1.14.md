# 0.1.14 — 2026-07-13

## Added

- **`sort`** input on **`reliefweb_search_jobs`** and **`reliefweb_search_training`**, mirroring the existing `search_reports` / `search_disasters` sort surface. Jobs accept `date.created:desc` (default), `date.closing:asc` (closing soonest), or `score:desc`; training accepts `date.start:asc` (default), `date.start:desc`, `date.created:desc`, or `score:desc`. `appliedFilters.sort` now echoes the resolved value instead of a hardcoded string. ([#12](https://github.com/cyanheads/reliefweb-mcp-server/issues/12))

## Changed

- **`reliefweb_search_training`** default sort is now `date.start:asc` (soonest-starting), replacing `date.created:desc`, so the documented "upcoming training" use case orders by start date without extra parameters. ([#12](https://github.com/cyanheads/reliefweb-mcp-server/issues/12))
- **`reliefweb_get_country` / `reliefweb_get_disaster`** — `keyContent`, `appealsResponsePlans`, and `usefulLinks` now surface only ReliefWeb's currently-active curated set; the historical `archive` half is no longer merged in. Output-field and doc descriptions updated to state the scope. ([#9](https://github.com/cyanheads/reliefweb-mcp-server/issues/9))
- **`reliefweb_get_disaster`** description now advises that `description` + `profileOverview` can together total tens of KB for major disasters — returned in full (like `reliefweb_get_report`), so call it only when the narrative text is needed. ([#9](https://github.com/cyanheads/reliefweb-mcp-server/issues/9))

## Fixed

- **`reliefweb_get_country`** no longer exceeds the client token limit for long-running crisis countries. The full `key_content` archive — 2,300+ entries for Syria against 3 currently-active — was merged into every response; normalization now surfaces the active set only, bringing the payload well within the context budget. ([#9](https://github.com/cyanheads/reliefweb-mcp-server/issues/9))
