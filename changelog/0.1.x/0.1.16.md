# 0.1.16 — 2026-08-06

## Changed

- **`reliefweb_search_reports` `format`** and **`reliefweb_search_disasters` `status`** are matched against ReliefWeb's verified closed vocabularies, ignoring case, spacing, and punctuation; an unrecognized value throws `unknown_format` / `unknown_status` naming the valid list instead of silently returning zero results. New `src/services/reliefweb/vocabularies.ts`. `UN Document` joins the format set (`Policy Document` and `Financial Report` were never real values); disaster status corrects `current` → `ongoing` and drops the nonexistent `archive`. ([#19](https://github.com/cyanheads/reliefweb-mcp-server/issues/19))
- **`include_archived`** now has real effect on `reliefweb_search_jobs` and `reliefweb_search_training`, reaching their `analysis`-preset archives, which were previously unreachable through the MCP surface. On `reliefweb_search_reports` it stays but is documented as inert — reports carry no archived class — and no longer flips the echoed `appliedFilters.preset`, which is now always `latest`. ([#18](https://github.com/cyanheads/reliefweb-mcp-server/issues/18))

## Fixed

- **`reliefweb://reports/{id}`** and **`reliefweb://disasters/{id}`** resources reject a malformed ID instead of silently coercing it to a different valid record. `parseInt`'s leading-prefix match let `4221539junk` resolve to report 4221539 and `1.5` to record 1; the whole URI segment is now matched against `^[1-9]\d*$` before any upstream call. New `src/mcp-server/resources/resource-ids.ts`. ([#13](https://github.com/cyanheads/reliefweb-mcp-server/issues/13))
