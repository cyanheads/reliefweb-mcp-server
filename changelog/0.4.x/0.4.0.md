# 0.4.0 — 2026-11-17

## Added

- **`reliefweb_search_jobs` `job_type`** filters on the posting type (Consultancy, Internship, Job, Tender/RFPs/EOIs, Volunteer Opportunity); comma-separated values match any. ([#42](https://github.com/cyanheads/reliefweb-mcp-server/issues/42))
- **`reliefweb_list_countries` `text`** looks a country up by whole words of its name or short name, case- and accent-insensitive. The crisis-briefing prompt and server instructions use it first. ([#43](https://github.com/cyanheads/reliefweb-mcp-server/issues/43))
- **Linked identifiers** — reports return `disasters: [{ id, name, glide? }]`; reports and disasters return uppercase `primaryCountryIso3` and `countryIso3s`; curated-link entries on country and disaster profiles, active and archived, return `reportId` parsed from a ReliefWeb node URL. ([#41](https://github.com/cyanheads/reliefweb-mcp-server/issues/41))
- **Job and training records** carry `countryIso3s`.

## Changed

- **Breaking — `reliefweb_get_disaster` and `reliefweb://disasters/{id}`** omit `profileOverview` when it is byte-identical to `description`, flagged by `profileOverviewSameAsDescription: true`; `sections: ["profileOverview"]` still returns it. ([#40](https://github.com/cyanheads/reliefweb-mcp-server/issues/40))
- **Breaking — `country` separators** on `reliefweb_search_reports`, `reliefweb_search_disasters`, `reliefweb_search_jobs`, and `reliefweb_search_training`: codes joined or followed by `;`, `/`, `-`, `&`, `+`, or `|` are rejected. Separate codes with commas or spaces (every listed country required); make one call per country for any-of. Each three-letter word is read as a code, so `SYR AND AFG` includes Andorra. ([#39](https://github.com/cyanheads/reliefweb-mcp-server/issues/39))
- **Breaking — multi-name `theme` (reports, jobs) and `career_category` (jobs, training) values**: several names in one value without commas (`Health Protection`), `|`-joined names, and comma lists whose entries pick a name only together (`Food, Nutrition, Gender`) are rejected as `unknown_theme` / `unknown_career_category`; separate full names with commas. ([#38](https://github.com/cyanheads/reliefweb-mcp-server/issues/38))
- **`theme` and `career_category`** resolve to canonical ReliefWeb names (a name in any case, `WASH`/`CCCM`/`NFI`/`ICT`/`M&E`/`HR`, or a word found in one name) and filter whole tags; comma-separated values are all required. ([#38](https://github.com/cyanheads/reliefweb-mcp-server/issues/38))
- **`reliefweb_search_training`** with no date bound covers listings starting from now plus listings with no start date, dated first; `appliedFilters.undatedIncluded` marks that scope. ([#37](https://github.com/cyanheads/reliefweb-mcp-server/issues/37))
- **`iso3`** is uppercase on `reliefweb_list_countries`, `reliefweb_get_country`, and the country resource. ([#41](https://github.com/cyanheads/reliefweb-mcp-server/issues/41))
- **`country` input** takes three-letter codes in any case, with a stray comma before the first code or after the last accepted. ([#39](https://github.com/cyanheads/reliefweb-mcp-server/issues/39))
- **`reliefweb-guide` skill** 1.0 → 1.1.
- **Development tooling** — framework skills and scripts synced to mcp-ts-core 0.13.22; `.env.example` documents `MCP_JWT_EXPECTED_AUDIENCE` and `MCP_JWT_EXPECTED_ISSUER`.

## Fixed

- **`theme` and `career_category` filters** return only the named tag's records (`Coordination`, `Information Management`). ([#38](https://github.com/cyanheads/reliefweb-mcp-server/issues/38))
- **`theme` and `career_category`** reject values naming no single tag — unknown names, words shared by two names (`Food`, `Management`), and near-miss phrases (`Food Security`) — as `unknown_theme` / `unknown_career_category`; they returned empty pages or other tags' records. ([#38](https://github.com/cyanheads/reliefweb-mcp-server/issues/38))
- **`language` and `training_language`** match case-insensitively. ([#38](https://github.com/cyanheads/reliefweb-mcp-server/issues/38))
- **`country`** rejects names, two-letter codes, and other non-codes, which returned empty pages, and `reliefweb_get_country` `iso3` rejects a non-code such as `1@!`, which answered `not_found`; both point to `reliefweb_list_countries` `text`. ([#39](https://github.com/cyanheads/reliefweb-mcp-server/issues/39))
- **Country filters and `reliefweb_get_country`** reach United Arab Emirates (`ARE`) and Andorra (`AND`).
- **`reliefweb_search_training`** empty-page notice no longer suggests checking the `format` spelling.
